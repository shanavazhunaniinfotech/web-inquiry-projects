    06 · Elly's task list, answered

    A safe, portable foundation.

    Is HTML5 + JavaScript enough? For the screens, yes. Not for member data.

    Logins, evaluations, evidence uploads and points must live on the server. I recommend PHP + MariaDB: it matches the code Elly already has (least rewriting), runs on almost any host, and is easy to move.

    Security before any real member

    Real server-side login with roles (member, coach, admin) · close the open assignments endpoint · remove the shared admin passphrase and hardcoded member ID · private file storage for evidence · keep Elly's CRM and private clients completely separate.

    Hosting: not GoDaddy

    A managed VPS (for example Cloudways or DigitalOcean) or David's own server, on a David-branded subdomain. No lock-in. The final choice depends on your domain and server decision.

    Test site + live site

    Separate development and production environments, so changes are tested before members see them.

    Safe server move

    Full backup, then a rehearsal restore, then record-by-record reconciliation. Only after that, and with your written approval, the real move.

    Easy updates for Elly

    A simple deploy script, so Elly can keep designing with Codex or Claude Code and publish to the test site in one command, then to live once approved.

    Database check

    I review the 39-table design against your data areas: accounts & membership, profiles, learning, placement & access, evidence & journey, incentives, operations.
